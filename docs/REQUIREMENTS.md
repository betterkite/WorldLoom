# WorldLoom 需求说明

## 产品目标

WorldLoom 是一个面向世界观与编年史创作的工作室。用户可以导入种子设定或半成品文稿，
将其编译为结构化世界数据，在人工审阅后合并为正史，并继续进行检索、续写、评测和导出。

核心原则：LLM 只产生待审变更；正史由可追溯的合并操作维护；版本只增不改；检索回答必须
附带证据，证据不足时明确说明。

## 功能范围

### 世界与正史

- 管理多个世界及其描述、历法和创作状态。
- 管理纪元、人物、势力、地点、物品、概念、事件和关系事件。
- 用 `Change → merge → WorldVersion` 管线记录每次正史变化。
- 记录并发冲突、删除墓碑、来源引用和回滚产生的新版本。

### 编译与创作

- 从文本、URL、PDF、EPUB 和批量文本导入素材。
- 自动分章；单个章节切片不超过 20,000 字。
- 编译采用分析与生成两步管线，长文本按块处理并持久化 `CompileRun/CompileChunk` 状态。
- 支持暂停、恢复、取消、推演候选、伏笔埋设与回收，以及章节定稿后回编译。

### 时间线、图谱与一致性

- 按虚构历法展示纪元、事件和因果边。
- 图谱支持关系、因果和推断边，节点类型编码、节点详情、邻居视图、多种布局和时间切片。
- 一致性检查覆盖时间、引用、关系、孤立数据和其他世界规则，并生成可追踪的 lint finding。

### 助手与评测

- 词法 BM25 与 pgvector 语义检索通过 RRF 融合。
- 远程 embedding 失败时回退本地 `Xenova/bge-m3`；两者都不可用时降级为词法检索。
- 回答逐条提供引用；无可靠证据时不编造结论。
- 支持检索命中率、LLM 答案评测、评分要点和排行榜。

### 输出与集成

- 导出 Obsidian 镜像 ZIP、游戏引擎 JSON 和结构化时间线。
- 提供 MCP Server：`query_world`、`compile_source`、`lint_world`。
- 提供技能管理、作用域、版本历史和审计恢复。

## 非功能要求

- 凭据只从运行时环境读取，不进入 Git、日志、错误响应或导出文件。
- 数据库迁移必须可重复执行；禁止以 `db:push` 代替正式迁移。
- 合并在世界级事务锁内串行化；重复且相同的变更幂等去重，冲突变更进入冲突账本。
- provider usage 不完整时，配置了预算上限的任务必须 fail-closed；未知价格保持 `null`。
- 任务需要有状态、心跳、过期回收和可恢复 checkpoint。
- 默认 Compose 配置只适合本地或受控主机；公网部署必须由外部网关提供认证、TLS、限流和备份。
- 质量门禁至少包括类型检查、严格 lint、测试、构建、浏览器 E2E、页面审计和迁移验证。

## 明确不包含

当前版本不提供公网多租户认证、多人实时协作、游戏 NPC 运行时、移动端应用，也不承诺
未经独立 worker、目标规模压测和生产恢复演练的高可用部署。
