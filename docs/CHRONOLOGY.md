# 编年日期、关系切片与旧游标

事件按所属版本的纪元顺序、年、月、日显示。完整日期相同的事件属于同一时刻；稳定显示
顺序不表示因果先后。只知年份、月份或缺失日期时保留时间范围，不借当前历法猜一个日期。
纪元顺序相同但不同纪元的先后也不能确定。

关系切片使用事件锚点。未来变更不会提前终止关系；同日互相冲突、重叠日期或已删除的
锚点会显示“状态不确定”及相关来源。没有锚点的基础关系与锚点丢失分开处理。一致性检查
只在原因的最早日期明确晚于结果的最晚日期时报告确定的因果倒置。

继续创作固定一个版本构造时间上下文。光标在该版本不存在时，需要重新选择；不回查旧版
事件冒充当前状态。自动推进光标遇到无法确定的最新日期时提示手动选择。同一最新日期
有多个精确同日事件时选择一个稳定代表，并提示这不代表它在同日内最后发生。

## 版本与迁移

`20261106150000_version_chronology_format` 仅为 `world_versions` 增加排序协议标记，
默认 `legacy`。原始历史内容和排序键不回写。新合并和追加回滚生成 `date-rank-v1` 版本，
全部变更完成后才计算新快照中有界的显示排名，避免大年份/纪元导致 INTEGER 溢出。
旧版本按自身日期和纪元提供只读时间投影；原始 `sortOrder` 保留供历史审计。

升级按本机部署说明执行迁移。不要手动批量更新历史事件。旧应用不写协议字段时，数据库
默认仍标记为 legacy；这只说明存储兼容设计，实际应用/worker 回退实证另见发布验收记录。

## API 游标

推荐指定版本和事件，例如：

```text
GET /api/worlds/<worldId>/relations?version=2&atEvent=<eventUid>
GET /api/worlds/<worldId>/graph?view=relations&version=2&asOf=<eventUid>
```

历史 `legacy` 版本仍支持 `relations?version=...&at=<旧sortOrder>`，按照原始存储键保留
原有粗粒度边界，响应附升级提示。该旧协议本来就无法区分同年月日，不会静默变成新排名。
`date-rank-v1` 版本收到数字 `at` 返回 **409 / legacy_time_cursor**，提示改用 `version`
和 `atEvent`；同时提供两种游标或非有限数值返回400。

`chronologyPosition` 是所选版本的显示位置，不是跨版本时间戳，也不能用来判定因果或作为
数字 `at` 传回。事件列表、时间线与导出携带此投影字段；图谱和关系响应携带版本，前端
缓存按版本区分。关系 `active: null` / `ambiguous: true` 表示状态不确定，不能当成已终止。

本说明记录行为契约，不代表验证已通过；实际结果以本次发布验收记录为准。
