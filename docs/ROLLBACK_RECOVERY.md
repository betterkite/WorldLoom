# 应用回退与维护恢复

回退前先确认**目标制品能读取当前完整数据库**。健康检查成功、数据库能连接或表数量相同，都不能证明兼容。应用和 worker 要分别确认制品身份、任务状态和数据约束。

旧客户端将评测成绩视为必填数值；含未评分 `NULL` 的新版数据库不能直接交给该客户端。已识别的旧制品：

- app：`sha256:34c34993a19806ad4a2f5ff8c122d78dc39726154a4711ea6b46e91d4038b2fb`
- worker：`sha256:dc4c39b03d752b8a387a63261167e7fc65f95fa992263e424a0a275de35af310`

不要填零、删除未评分记录、清空任务或累计用量来满足旧版约束。兼容检查失败时停止直接切换。相关数据含义见[评测说明](./EVALUATIONS.md)。

## 不兼容时的只读维护路径

v0.1 本机单人部署采用以下维护路径查阅旧版本中的历史资料。它使用**独立的旧恢复点**，不提供回退期间的创作写入，也不保证旧视图包含恢复点之后的数据。它不等于保持当前完整数据的可写应用回退。

1. 进入维护窗口，停止接收新写入，停止当前 app/worker，确认正在执行的任务已经结束或有持久化恢复状态。
2. 保留当前完整数据库和新的可恢复备份；记录备份摘要、迁移、任务/块状态、世界版本和累计用量。验证恢复点可读，不覆盖唯一副本。
3. 把经过核对的旧备份恢复到**另一个数据库**。不要对当前数据库执行旧结构恢复或降级操作。
4. 为旧应用创建仅能读取旧恢复库的独立数据库角色；不授予业务表的 INSERT、UPDATE、DELETE 或结构修改权限。核对连接目标和实际权限，不只依赖界面隐藏按钮。
5. 旧恢复库必须没有待执行或运行中的编译/索引任务。不能通过删除任务来通过此检查；不满足条件时停止这条路径。旧 worker 只能按明确的维护方案运行，不承担新任务。
6. 旧入口只用于历史资料查阅。保持写入入口不可用，明确标识恢复点时间，不把历史视图当成当前进度。

当前恢复点之后的数据必须始终留在当前数据库或经过校验的当前备份中。若需要让旧版继续接受写入，就涉及额外的数据合并和冲突方案；本路径不支持这种用法。

## 返回当前版本

1. 停止旧 app/worker，保留旧恢复库供核查，不把它覆盖回当前数据库。
2. 以核对过的当前制品和当前恢复点启动 app；先验证原文、未评分记录、世界版本、待审 Change、任务及累计用量。
3. 再启动一个当前 worker。已保存结果的编译应继续恢复；取消任务不得被重新领取，模型产物仍只进入待审，不能自动合并正史。
4. 检查 worker 重启不会重复写入。未确认恢复状态之前不开放创作写入。

恢复使用当前保留库时，应核对维护窗口前后的数据；使用当前备份重新恢复时，还须按[本机部署说明](./LOCAL_DEPLOYMENT.md)验证完整恢复与用量。不要将旧版没有记录的调用窗口伪造为零用量。

## 验收记录

记录精确新旧 app/worker 身份、两个恢复点摘要、只读权限、实际运行角色、检查结果、资源峰值和清理结果。区分：

- 旧版直接读取当前库的兼容检查；
- 只读历史维护及返回当前版本；
- 保持当前数据且可继续写入的旧版回退。

三者不能互相代替。本文件是操作边界，不是验收证据；未完成适用验证时，不填写 `WORLDLOOM_MIGRATION_ROLLBACK_CONFIRMED=true`。结果应填入[部署证据模板](./DEPLOYMENT_EVIDENCE_TEMPLATE.md)，累计用量的兼容范围另见[部署用量说明](./LLM_USAGE_ROLLOUT.md)。
