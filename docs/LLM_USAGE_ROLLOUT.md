# 累计用量的升级、应用回退与数据恢复

2026-10-03：本文件是 #3 的源码兼容性分析及待执行检查表，不是迁移、部署或回滚实证。
用户要求“先修复，暂不运行验证”仍有效；以下步骤没有执行，不授权连接数据库、运行
模型、更新服务、删除数据或上传。个人消费无上限、统计不展示 embedding 余额的选择不变。

## 本次增量的兼容范围

新增迁移 `20261001100000_llm_usage_calls` 只包含一张表和两个索引的 CREATE；未 ALTER、
DROP 或回填已有业务表。表不引用 World，token 可为空，状态、token 对和生命周期由
CHECK 限制。源码见 [迁移](../prisma/migrations/20261001100000_llm_usage_calls/migration.sql)
和 [模型](../prisma/schema.prisma)。这是统计增量的结构事实，不证明完整 v0.1 候选的
其他迁移、版本、编译/索引状态或旧制品均可回退。

以下 O 指已读的统计功能加入前源码 `71161574d232fa072083a365cb2e4bc39619e472`；
N 指含新记录器/API 的候选源码。O 不是已核实的现运行镜像或获批回退制品，N 也未构建
验收。D0 指没有统计表的数据库状态，D1 指统计迁移成功且实际结构/权限已验证的状态；
二者不是整个迁移历史相同的承诺。

| 应用与数据库组合 | 源码推断与用量影响 | 发布/恢复判断 |
| --- | --- | --- |
| O + D0 | 旧客户端没有独立累计记录器，单任务用量不等于跨操作总量 | 不能声称已交付新的累计统计 |
| N + D0 | 记录写入会失败；观察层不因此拒绝模型，统计读取失败返回固定 503，不生成零总量 | 不可据模型可用或服务 ready 当统计升级成功；可能发生未记录的付费尝试 |
| O + D1 | 保留的表本身不增加旧客户端的记录能力；新累计 API/UI 也不在 O 中 | 仅是应用回退的源码兼容线索；回退期间可能存在统计空窗，不 DROP 表 |
| N + D1 | 目标组合；逐尝试写入与完整聚合依赖实际权限、同库和候选制品 | 仍须验证迁移、记录、重启、API/UI、失败与恢复，不以表存在或 API 空统计证明完整 |
| O/N 混用 + D1 | 只有带记录器的调用路径参与累计；Web 的成功读取不能证明旧 worker 已记录调用 | 不作为正常首版拓扑；记录切换窗口及所有进程身份后完成同候选切换 |
| 恢复较旧 D1 快照后使用 N | 只能保留快照时点已有记录；其后的创作和统计可能丢失，pending 也不代表任务仍在运行 | 先确认数据损失窗口与恢复后任务状态；不能按 provider 余额或猜测 usage 补齐 |

N + D0 的判断来自 [记录器](../src/lib/llm/usage-tracking.ts)、
[参数化 SQL](../src/lib/llm/usage-store.mjs)和 [统计 API](../src/app/api/llm/usage/route.ts)，
不是在用户库制造缺表故障后的观察。O 的判断来自上述本地 Git revision 的 client 源码。
应用回退是否可用，须对精确回退制品和完整数据库状态另行证明。

## 待恢复验证后，按此顺序验收

1. 固定本次候选源码、锁文件、迁移文件及目标制品身份，同时选定精确回退制品。
   为获批串行低资源环境完成工程检查；隔离库先验证完整干净迁移链，再验证从实际
   升级基线迁移。现有 owned-schema 测试只应用三条统计 DDL，不替代完整迁移链。
2. 记录实际 app/worker/migrate 的制品、数据库目标、角色、缓存及适用配置；app/worker
   声明 `build: .`，migrate 声明相同 context 的独立 target，不证明当前容器已经同源。
   配置中同库也不证明运行连接一致。
   所有记录脱敏，凭据和用户原文不放入证据附件或 Git。
3. 在用户数据库变更前建立可保留的备份/恢复点，验证隔离恢复、范围、权限、保留期
   和可接受损失窗口。`db:backup:drill` 正常结束删除 dump，不能代替这个恢复点。
   备份中还没有统计表时，不把它标成统计表恢复已验证。
4. 选维护窗口停止新任务入口并确认在途请求、任务和可能迟到的统计写入状态，再按
   获批方案处理 app/worker 切换。不能仅以 pending 行判断在途任务，不能通过强制
   清空任务/统计或直接杀停用户服务来制造安静窗口；不确定时停止升级并请人决定。
5. 使用精确候选的正式迁移流程 `db:deploy`。Compose 源码把 migrate 成功作为 app/
   worker 的启动依赖，但旧迁移容器的历史退出码不能证明新候选迁移已执行。
   失败则不推广候选；先核对迁移历史、实际对象和错误关联，不推定 DDL 全部回滚，
   不盲目反复执行、标记迁移成功、修改迁移历史、`db:push`、reset 或 DROP 统计表。
6. 对同一候选的 Web 与 worker 分别验收记录路径。先使用无模型的合成元数据验证
   已知/未知/真实零、重复/迟到结束、大整数、换进程及待结算状态；真实服务和模型
   链路另需适用授权，不能把 mock 或原生小 fixture 当作已运行的 Web/worker。
7. 检查聚合读取权限与只读事务设置、查询/锁/获取期限及连接设置恢复；读取故障应
   保留局部错误而非零值。检查 API/卡片快照、重试后逐尝试累计、重启累计和删除
   测试世界后统计保留，再登记实际日志、资源与恢复结果。
8. 对精确回退制品验证保留 D1 的应用回退及再次前进，核对整个候选的任务/领域状态
   兼容性与统计空窗。完成实际证据后再填写本机确认项；仍不自动批准 v0.1 或上传。

这是检查顺序，不是可直接运行的自动部署脚本。维护窗口、停启对象和回退方案必须绑定
实际资源与适用授权，不能从本文推导删除容器/卷/用户世界、终止后台或调用付费模型的权限。

## 健康检查不是迁移/统计验收

[live](../src/app/api/health/live/route.ts)只证明进程响应，
[ready](../src/app/api/health/ready/route.ts)只查询 `SELECT 1`；它们不检查统计表、约束、
记录权限、worker 制品或统计完整性。`/api/health` 还可能探测 provider，不用它代替
无模型的迁移检查。离线本机 preflight 不连接数据库，也不能证明这些事实。

统计 API 200 说明该次聚合读取和契约解析成功，不证明记录写入权限、历史完整或当前
worker 正常。空表给零调用/未知 token 是“无已记录行”，不是账户未花钱的证明。
Web 的进程内写入故障计数重启清空，也不涵盖 worker；须分别核对脱敏日志和真实记录。

## 应用回退与备份恢复分开决策

- 当前完整候选还包含 `eval_runs.score` 可空迁移。2026-11-07 已在隔离合成库确认：
  旧 app `34c34993a198…` / worker `dc4c39b03d75…` 中的 Prisma 客户端读取空成绩
  会报 `P2032`。因此上文仅针对累计用量表的 O + D1 矩阵，不能用于批准整个候选直接
  换回这两个旧版。具体证据边界和处置见 [评测兼容说明](./EVALUATIONS.md)。
- 应用回退优先保留新增表及数据，但必须使用已验收的回退制品；这是本次统计增量
  的建议路径，不是完整候选任意回退的保证。旧源码不再记录的窗口要如实登记。
- 恢复迁移前备份会回到 D0；新应用不能据此声称累计可用。重新迁移也不会找回备份
  时点后丢失的创作/统计，不从 CompileRun 重算并伪装为逐调用历史。
- 恢复迁移后备份也只恢复对应快照。保存恢复前的当前恢复点、记录确切影响和选择，
  核对任务/版本及应用功能，再恢复日常使用；不能自动覆盖当前用户库。
- 缺漏的调用不制造零 token、伪造 pending 行或从已知 token 推导完整费用。具体的
  切换/回退/恢复窗口记录在私有运维证据中，API 本身不能自动识别所有遗漏区间。
