# WorldLoom 后续任务

任务按风险和依赖排序。已完成能力不在此重复登记，当前开放项见 [ISSUES.md](./ISSUES.md)。

## P0/P1：发布前必须完成

1. 关闭 [#11](https://github.com/betterkite/WorldLoom/issues/11) 的 Sharp/libvips 与 `client-only` 许可文本缺口，完成原生组件、浏览器 bundle 与基础镜像的制品清单勾稽和合格人员复核；严格镜像审计必须通过。
2. 将本地已验证的 [#7–#10](./ISSUES.md) 候选交由远端 CI 和目标部署环境验收；在 #11 发布门禁与部署安全证据齐备前，不以本机候选替换正式服务或宣称可发布。
3. 在实际部署环境完成外部认证接入和限流并发压测。
4. 完成跨主机 PostgreSQL 备份恢复演练和迁移回滚演练。
5. 验证独立 worker 的 lease、重试、幂等写入、容量和故障恢复。
6. 为正式 provider 填写真实价格和 token 预算，并重新运行严格 preflight。
7. 在目标硬件上复跑检索、编译和容器资源基准。

## P2：按使用信号推进

- 真实创作试用：用连续数日的半成品素材记录生成质量、耗时、成本和工作流阻塞。
- 技能发布审批、权限和批量管理。
- 当单世界实体与事件达到数千且延迟明显时，评估 PostgreSQL FTS/GIN 索引。
- 当表单复杂度继续增长时，统一迁移到 TanStack Form。

## 明确暂不做

公网多租户认证、多人实时协作、游戏 NPC 运行时、移动端应用和未经规模验证的高可用集群。
