# 本机累计模型用量

2026-10-01：按用户决定，本机个人使用不设消费额度，只显示累计用量，由使用者判断。
本文描述已补入源码的设计，不是已部署事实。迁移、测试、生成 Prisma Client、构建与界面
验证尚未执行；现运行的旧服务未升级。恢复验证前不要将本节标记为验收通过。

## 统计口径

- 覆盖统一 `chat()` 客户端的每次调用尝试，创世、编译、继续创作、问答、评测与 MCP
  中使用该客户端的调用共用统计。重试是不同尝试，不能只计算最终成功的一次。
- 缺失凭据、配置或预算在请求前拒绝的操作，不记录为模型调用；调用开始后失败也保留
  尝试记录。provider 返回的完整、非负安全整数输入/输出 token，成功或失败均计入已知用量。
- 不完整或非法 usage 保留 `null`，不推算或记作零。待结算记录可能是正在请求，也可能
  是进程中断后没有终结记录，不能仅凭它认定任务仍在运行。
- 累计只包含此功能启用后成功写入的记录，最早记录时间不等于功能准确启用时间。
  不回填旧 CompileRun，不冒充 provider 全部历史、实际人民币支出或账户余额。
- 不计 `/models` 连接探测或 embedding。读取统计不调用 provider，不展示 embedding 余额。

## 数据与界面

`LlmUsageCall` / `llm_usage_calls` 独立于世界，不设置 World 外键；删除世界不清空累计量。
每行仅保存随机尝试 ID、profile、模型、开始/结束时间、状态及输入/输出 token。
不保存提示词、回复、凭据、provider 原始响应、价格或正文错误信息。

`src/lib/llm/usage-tracking.ts` 使用 `usage-store.mjs` 中共用的参数化 SQL 写入待结算行，
结束时 upsert 终态；这层不创建连接、读取环境或调用模型。
开始写入迟到不得覆盖终态，重复结束不得重复累计或改写已结束行。数据库约束限制状态、
token 对和生命周期。跨操作、Web/worker 及进程重启的累计依靠同一持久化数据库；必须
保留并备份数据库卷，删除/替换数据库或恢复较旧备份会影响统计范围。

`GET /api/llm/usage` 是单次聚合只读查询，返回总量、按 profile/模型分组、最早记录和
当前 Web 进程诊断；响应 `no-store`。用量用 BIGINT 存储、聚合后以十进制字符串传输，
前端以 BigInt 格式化，避免长期累计经过 JavaScript Number 丢失精度。

世界总览卡片展示调用尝试、已知输入/输出/总 token、完整/未知用量、待结算/中断和失败
次数，以及记录起点。失败与未知不是同一维度：失败也可能有已知 token。卡片提供手动
刷新；读取失败保留局部错误，不伪造零、不阻断世界列表和导航。

卡片标明这是非实时统计，并显示服务器 `updatedAt` 快照时间；正在刷新或刷新失败时，
此前成功值只能标成“上次成功快照/非当前值”。首次失败不创建零快照；后续成功读取才
替换缓存。长十进制值可换行，不通过 Number 舍入或省略真实数字。进程内诊断属于该
快照时刻，旧快照也不能证明当前进程或 worker 正常。

前端只读请求使用 10 秒计时期限（包含响应头后的正文读取，受浏览器调度影响），接入
Query 的取消信号；离开页面或超时可取消请求并允许后续手动重试。响应正文按实际字节
限制为 256 KiB，只保留固定有界缓冲；Content-Length 仅作预检，不能凭它信任大小。
超限整体报错，不截断分组、不回退为零，也不是消费/token 额度。数据分组若实际超过
此界限，须完善聚合/分组接口契约后重新验收，不绕过上限或隐瞒不完整统计。
JSON、UTF-8、网络和正文读取错误均用固定消息，不保留原始错误正文或 cause。
取消/失败响应的正文清理不增加无界等待；浏览器取消不证明服务端 SQL 已取消，也
不提供浏览器整体内存、数据库负载或记录器查询的全局限制。

## 记录失败与费用保护

统计是观察能力，不是费用额度。每次数据库写入最多等待 1 秒，失败或超时只发出固定
脱敏日志，不因数据库记录故障拒绝模型使用。这个等待上限不取消底层查询，查询可能
稍后完成；SQL 用幂等键与非回退条件保护迟到写入。它不是数据库查询或连接的全局超时。

两次写入都失败且进程退出时可能完全没有该尝试的记录。当前进程的写入失败/超时计数
只在内存中，重启会清空；总览 API 不能证明 worker 无记录故障，须结合 worker 日志。
不承诺完整财务记账或零丢失，未知调用与缺漏也不应据已知 token 推导完整账单。

可选 budget guard 仍独立存在，显式非法配置仍报错；个人无额度模式不要求为了使用统计
而设置预算变量。模型输出能力、分章大小、并发/内存保护保留。未来对外部署仍遵守
[DEPLOYMENT_SECURITY.md](./DEPLOYMENT_SECURITY.md)，本机选择不放宽 strict 生产契约。

2026-10-03 provider 错误反馈增量（仅源码）：非成功 HTTP 响应不读取/缓冲正文，不再等待
正文 cancel promise 完成；请求 transport 被发出 abort，清理异步 best-effort，拒绝、同步
异常或长期未结算均不替换原有 HTTP 错误。这样用量终结路径和已有有界重试不被清理
等待占住；失败正文不解析 usage，因此记录仍是失败/未知，不伪造零。401/402 不增重试，
429/5xx 仍按原 profile 有界重试、逐尝试记录，预算/消费策略不改。

只读取 `/models` 响应头的探测也尝试 abort/清理成功及失败响应正文，保持既有缓存和状态
口径，不解析模型目录、不计入 chat 用量或查询余额。abort/清理尝试不是 provider 请求、
实际费用或底层连接已经停止的证明；不提供所有响应的全局内存/查询上限。相关 stalled /
reject / sync throw、重试及探测 mock 用例未执行，现运行服务未更新，不登记 runtime PASS。

同日成功 chat JSON 读取增量（仅源码）：不再直接调用 `response.json()`，改为单响应
4 MiB 的实际字节读取边界。Content-Length 只作超限预检；缺失、低报或非法长度不能绕过
逐块检查。16 KiB 起步的缓冲按需增长且不超过此边界，不积累无界 chunk 数组；完整读取
后才进行严格 UTF-8 解码与 JSON 解析，边界包含 choices、usage 和其他元数据/推理内容。
超限整体拒绝，不截断回复、不提取部分 usage；该尝试保留失败/未知用量，可选预算账本
仍按原规则保留未知预留，不推定为零或退款。个人无消费额度策略不变。

客户端将超限映射为 `llm_response_too_large`，API 给固定脱敏消息和 correlation ID、
HTTP 502，无 Retry-After；这不是预算 429，chat 不对此错误自动重试，避免重复付费请求。
读取正文与现有 profile 请求期限共用信号；正文读取忽略 abort 时也竞争返回，并释放
自身缓冲引用/读取锁、观察迟到拒绝，不等待可能无法结束的 cancel promise。此处不新增
token/价格限额，也不证明 transport、provider 执行或计费已经停止。

4 MiB 是主动读取的 wire JSON 边界，不是整机/进程堆上限：缓冲扩容、新旧分配、字符串
解码、JSON 对象、transport 自身 chunk 与 GC 仍可能额外占用内存。它也不覆盖 embedding
客户端、统计数据库或所有请求的全局并发。最大支持输出/元数据是否适配此值仍须低资源
验收；如不适配，应依据实测调整契约并重新验证，不用截断或关闭保护制造通过。
新增 `llm-response-body` 合成 stream 用例及 chat/API 用例均未执行，当前服务未升级。

后续 embedding 增量（仅源码）：远程非成功 HTTP 不再 await response.text，不读取错误
正文；发出 transport abort 后 best-effort 清理，清理拒绝、同步异常或不结算不能阻挡
既有本地 fallback。成功正文复用有界 reader，显式单批 16 MiB 实际字节边界，与 chat
默认 4 MiB 分开；Content-Length 仍只作预检。现有 30 秒批请求期限覆盖正文读取，
正文忽略 abort 时也竞争返回，不等待清理；不将 abort 当作连接/provider/计费已停止。

解析结果须为 data 数组，数量等于本批输入、index 为 0..count-1 的唯一安全整数、
每个向量维度匹配配置、每个值是有限 number。不转换字符串，不接受缺失/重复/越界
index、错误维度、非有限值或部分向量；非法 JSON/格式/超限/正文超时均转为脱敏
EmbeddingError 后尝试本地。后续批失败也对原始整组文本回退本地，不返回前面远程
向量加后面本地向量的混合结果。本地实际不可用时保留 typed failure，由已有检索
路径诚实降级词法；本轮未改正史、语义索引模型身份或数据库。

16 MiB 只限制单批主动 wire JSON 读取，含全部元数据；它不是整体内存、整个输入向量
累计、本地推理、总请求/并发或消费额度。缓冲/对象/transport 的额外分配仍存在，最大
批数/维度/元数据的适配和真实 fallback 资源仍须低资源验收。新增 llm-embeddings 用例
将配置/远程 fetch/本地推理全部替换为 mock，不初始化模型、连接 DB 或计入累计 chat
统计。stream/HTTP402/非法形状/整组回退/双失败/期限用例和共享 reader 用例均未运行，
不证明真实缓存可用、推理、向量索引/查询或词法降级通过；当前服务未更新。

## 语义索引的模型身份与手动刷新

索引保存实际生成向量的后端、模型、维度及本地量化类型所构成的空间标识，查询只与
同一标识的向量融合。远程失败后整组回退本地，索引记录本地身份；远程恢复后若查询
身份不同，则使用词法检索。模型名、维度、量化或远程端点变化，以及仅保存旧模型名的
历史索引，均不能继续作为匹配索引使用。标识描述配置，不证明同名远程模型或本地
权重文件的内容未被替换；替换模型时应更改模型版本标识并重新索引。

在世界的「运行概览」点击「重建语义索引」可按当前配置重建；该操作可能请求远程
embedding 或加载本地模型，按需要手动执行。读取 `GET /api/worlds/:id/semantic-index`
只返回状态，不启动或重试索引；显式 `POST` 才执行手动重建。正常合并后的后台索引
流程保持原有行为。不自动重建身份不明的历史索引，不迁移或改写正史内容。

上述身份传播、混合空间拒绝和状态只读行为有合成向量/HTTP/数据库替身检查；这些
检查不证明真实模型推理、实际 PostgreSQL 或当前已部署服务通过验收。
